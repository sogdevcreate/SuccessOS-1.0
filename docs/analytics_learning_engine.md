# Analytics & Learning Engine

The analytics subsystem records provider-attributed, aggregate performance snapshots. It separates observed metrics from analysis and never requires viewer-level personal data.

Learning reports keep observations, patterns, correlations, hypotheses, signals, and recommendations distinct. Recommendations require evidence and provenance; unsupported causal claims are rejected. A Creator, Reviewer, and Director must explicitly move a recommendation through review before it can create a versioned, reversible, disableable optimization policy.

No provider integration, code rewrite, prompt rewrite, or silent behavioural change is part of this architecture. Provider absence is represented as an unavailable analytics state. Analytics and learning failures do not invalidate completed publishing or final masters.
